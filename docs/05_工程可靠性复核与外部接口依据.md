# 第一阶段工程可靠性复核与外部接口依据

## 1. Sujet 数据映射

当前公开数据集：

```text
sujet-ai/Sujet-Finance-Instruct-177k
```

官方数据卡给出：

```text
总记录 177,597
qa 38,801
qa = direct-answer finance questions that don't require additional context
```

本工程只读取：

```text
task_type == "qa"
user_prompt → audio
answer → assistant target
```

## 2. Qwen3-Omni 音频采样率

当前官方 `Qwen/Qwen3-Omni-30B-A3B-Instruct` 的 `preprocessor_config.json`：

```text
feature_extractor_type = WhisperFeatureExtractor
sampling_rate = 16000
```

所以正式训练资产统一为 16 kHz。

## 3. ms-swift 多模态数据契约

当前官方自定义数据集文档中：

```text
messages 为必需 key
audios 保存音频 path/url
<audio> 表示音频插入位置
```

官方同时建议多模态资源优先使用绝对路径，因此本工程默认输出绝对 WAV path。

## 4. Edge-TTS

当前 PyPI 最新公开版本为 `edge-tts 7.2.8`（2026-03-22），本工程固定：

```text
edge-tts==7.2.8
```

生产代码使用官方 Python `Communicate(...).save(...)` 接口；voice 使用运行时发现，不硬编码永久 voice 名称。

## 5. 风险控制

Edge-TTS 是在线服务，因此工程不能假设：

```text
永不限流
永不超时
接口永久不变
```

代码已加入：

```text
bounded concurrency
retry
exponential backoff
resume
atomic MP3/WAV write
runtime voice snapshot
failure manifest
```

## 6. 当前测试边界

本次交付环境无法访问 Hugging Face/Edge 外网，因此只实际跑了 mock 全链路；真实在线调用必须在目标服务器先跑：

```bash
bash run_build.sh --mode live-smoke --limit 5
```

该 gate 通过后才进入 full。
