# 音频 QC 与结果验收（v1.0.1）

最终以 `<output-root>/reports/FINAL_BUILD_REPORT.md` 为第一入口。

## 1. 技术 Audio QC

必须确认：

1. `final_validation_error_count == 0`；
2. `audio_qc_pass_rows == final_rows`；
3. WAV 为 16 kHz、mono、PCM16；
4. `messages` 中只有一个 `<audio>`；
5. `audios` 只有一个绝对 WAV 路径；
6. assistant target 与 `manifests/provenance.jsonl` 中原始 `assistant_text` 完全相同；
7. user message 不出现原问题 transcript。

## 2. 技术 QC 不等于“语音内容正确”

`Audio QC` 检查的是：

```text
可解码 / sample rate / channels / codec / duration / finite samples / RMS 非静音
```

它**不能证明音频一定包含可理解英语语音**。例如单频正弦测试音也可能满足“非静音 + 16 kHz + PCM16”，因此技术 QC 会通过。

所以真实 smoke/live-smoke/full 还必须满足：

```text
manifests/edge_voice_snapshot.json -> backend == "edge"
prepared/tts_plan.jsonl            -> tts_backend == "edge"
```

`run_build.sh` 已自动调用 `scripts/07_verify_tts_backend.py` 做这一 provenance gate。

## 3. 语义可听验收

在 `smoke` 或 `live-smoke` 后随机试听 3～5 条：

```bash
find ./data_test/smoke_edge/audio_16k -name '*.wav' | head
```

要求：

- 能听到完整英语金融问题；
- 没有纯音、长静音、截断或明显乱码；
- 金融缩写、百分比、bps、10-K/10-Q、金额等发音基本可理解。

`offline-smoke` 使用 `test-tone`，其音频**故意没有语义**，只能用于结构回归，不能用于上述试听验收或训练。
