# 金融 Qwen3-Omni 第一阶段音频数据集构建工程方案
## Sujet-Finance-Instruct-177k → Edge-TTS → Qwen3-Omni Audio-to-Text SFT Dataset

> **数据源：** `sujet-ai/Sujet-Finance-Instruct-177k`  
> **使用子集：** `task_type == "qa"`  
> **语言：** English-only  
> **任务：** 金融文本 QA → 金融音频输入 / 文本答案 QA  
> **TTS：** Edge-TTS  
> **正式音频格式：** 16 kHz / mono / PCM16 / WAV  
> **目标训练格式：** Qwen3-Omni / ms-swift `messages + audios` JSONL  
> **第一阶段范围：** 只负责生成可供后续 Qwen3-Omni SFT 使用的数据集，不运行 Qwen3-Omni、不训练模型  
> **监督答案策略：** Sujet 原始 `answer` 原样保留，不做内容审计、改写或质量评分

---

# 1. 工程目标

第一阶段需要将 Sujet 的英文金融 direct QA：

```text
user_prompt → answer
```

转换为：

```text
spoken(user_prompt) → answer
```

即：

$$
(q_i,a_i)
\rightarrow
(x_i^{audio},a_i),
$$

其中：

- $q_i$：Sujet `user_prompt`；
- $a_i$：Sujet `answer`；
- $x_i^{audio}$：由 `user_prompt` 经 Edge-TTS 生成并标准化后的 WAV。

最终数据必须满足：

```text
Audio input:
    spoken financial question

Text target:
    original Sujet answer
```

不构造 ASR 数据，不把问题 transcript 作为文本输入，不生成语音答案。

---

# 2. 工程边界

## 2.1 本阶段执行

- 下载并冻结 Sujet 数据；
- 筛选 `task_type == "qa"`；
- 提取 `user_prompt` 与 `answer`；
- 对 `user_prompt` 做确定性金融发音规范化；
- Edge-TTS 生成英文问题音频；
- FFmpeg 转换为 16 kHz mono PCM16 WAV；
- Audio QC；
- 稳定划分 train / valid；
- 生成 Qwen3-Omni / ms-swift `messages + audios` JSONL；
- 生成 provenance、失败日志和 build report；
- 支持 retry / resume / deterministic rebuild。

## 2.2 本阶段不执行

- 原始 `answer` 语义检查；
- answer 事实核验、分类、重写或人工审核；
- 其他金融文本数据集接入；
- Qwen3-Omni 模型下载；
- Qwen processor runtime；
- LoRA / SFT；
- GPU / CUDA 训练；
- 推理与 benchmark；
- 多轮音频；
- audio-to-audio；
- 噪声、RIR、codec 等复杂增强。

# 3. 输入数据规范

## 3.1 数据源

```text
sujet-ai/Sujet-Finance-Instruct-177k
```

第一阶段只使用：

```python
row["task_type"] == "qa"
```

该子集名义规模约 38,801 条，实际读取数量由代码运行结果记录。

---

## 3.2 字段映射

源字段：

```text
user_prompt
answer
task_type
dataset
```

工程映射：

```python
source_user_text = row["user_prompt"]
assistant_text   = row["answer"]
upstream_dataset = row["dataset"]
```

约束：

```text
user_prompt → TTS
answer      → assistant target
```

不得使用 `inputs` 作为 TTS 主输入。

---

## 3.3 Answer 处理规则

`answer` 只做：

```text
读取
→ 保存
→ JSON 序列化
→ 写入 assistant message
```

满足：

$$
a_i^{final}=a_i^{source}.
$$

不得基于 answer 的语义、长度、类别、正确性或时效性修改样本。

若源记录缺失必要字段或无法正常序列化，记录技术失败并进入 failure manifest。

# 5. Stable ID 与数据可复现性

每条源记录必须生成稳定 ID。

建议：

```python
sha256(
    source_dataset
    + source_row_id
    + user_prompt
)
```

最终：

```text
sample_id = 64-char sha256
```

用途：

- WAV 文件名；
- manifest 主键；
- split；
- voice 分配；
- rate 分配；
- retry / resume；
- source → audio → JSONL 全链路追踪。

推荐音频分片：

```text
audio_16k/
├── 00/
├── 01/
├── ...
├── fe/
└── ff/
```

文件：

```text
audio_16k/<sample_id[:2]>/<sample_id>.wav
```

# 6. 数据划分

第一阶段只输出：

```text

```

默认：

```yaml

```

```text

```

# 7. 金融 TTS 文本规范化

## 7.1 基本原则

必须同时保存：

```text
source_user_text
tts_text
```

例如：

```text
source_user_text:
A 10-year Treasury yield rose 25 bps to 4.50%.

tts_text:
A ten-year Treasury yield rose twenty-five basis points to four point five zero percent.
```

TTS normalization 只解决发音问题，不重写问题语义。

禁止使用 LLM 改写 `user_prompt`。

---

```text
normalizer_version = fin_en_tts_norm_v1
```

并通过单元测试验证数字、百分比、金额和单位不会被错误改写。

# 8. Edge-TTS 生成策略

## 8.1 样本数量

默认：

```text
1 QA = 1 audio
```

第一阶段不对同一问题生成多个 voice variant。

---

## 8.2 Voice Pool

运行时动态读取当前 English voices：

```bash
edge-tts --list-voices
```

保存：

```text
manifests/edge_voice_snapshot.json
```

允许 locale：

```text
en-US
en-GB
en-AU
en-CA
en-IE
en-IN
```

代码必须以运行时实际存在的 voice 为准。

---

## 8.3 Voice / Rate 分配

使用 `sample_id` 做确定性映射：

```text
sample_id
→ voice_index
→ rate_index
```

默认 rate：

```text
-4%
+0%
+4%
```

默认 pitch：

```text
+0Hz
```

相同 build config 下，同一 `sample_id` 必须始终得到相同 voice 和 rate。

---

## 8.4 并发与容错

默认：

```yaml
concurrency: 4
max_retries: 5
```

必须支持：

```text
bounded concurrency
timeout
retry
exponential backoff
resume
temporary file
atomic rename
failure manifest
```

不得因为单条 TTS 失败终止全量构建。

# 9. 音频标准化

Edge-TTS 中间音频通过 FFmpeg 转为正式训练资产：

```bash
ffmpeg -y \
  -i input.mp3 \
  -ac 1 \
  -ar 16000 \
  -c:a pcm_s16le \
  output.wav
```

正式音频固定：

```text
sample rate: 16000 Hz
channels: 1
codec: PCM signed 16-bit little-endian
container: WAV
```

MP3 只作为中间文件。

默认：

```yaml
keep_raw_mp3: false
```

WAV 通过 QC 后删除临时 MP3。

---

# 10. Audio QC

每个进入最终训练集的 WAV 必须通过以下技术检查：

```text
file exists
file size > 0
decode success
sample_rate == 16000
channels == 1
PCM16
duration >= 0.5 s
finite samples
not all silence
sample_id ↔ audio path unique
```

默认主训练音频上限：

```text
duration <= 60 s
```

超过 60 秒的音频不做文本语义判断，单独进入：

```text
data/long_audio/
```

不写入主 `train.jsonl` / `valid.jsonl`。

Audio QC 结果必须写入：

```text
manifests/audio_qc.jsonl
```

# 12. Qwen3-Omni / ms-swift 最终训练格式

最终训练文件只保留模型训练需要的字段：

```json
{
  "messages": [
    {
      "role": "system",
      "content": "You are a professional, accurate, and careful financial assistant."
    },
    {
      "role": "user",
      "content": "<audio>Please answer the financial question in the audio."
    },
    {
      "role": "assistant",
      "content": "ORIGINAL SUJET ANSWER"
    }
  ],
  "audios": [
    "/absolute/path/to/audio_16k/ab/abcdef.wav"
  ]
}
```

---

## 12.1 Transcript Leakage 约束

禁止：

```json
{
  "role": "user",
  "content": "<audio>What is modified duration?"
}
```

必须：

```json
{
  "role": "user",
  "content": "<audio>Please answer the financial question in the audio."
}
```

原 `user_prompt` 只进入音频，不作为文本 user content。

---

## 12.2 Audio Token 对齐

每条单轮样本必须满足：

```text
count("<audio>") == len(audios) == 1
```

并且：

```text
audios[0]
```

必须指向该记录对应的已通过 QC 的 WAV。
