# v1.2 金融域过滤最小修复说明

## 1. 为什么只改 source 阶段

原流水线为：

```text
Sujet source
→ task_type == qa
→ qa_source.jsonl
→ TTS plan
→ Edge-TTS
→ Audio QC
→ final JSONL
```

污染发生在 `task_type == qa` 之后、写入 `qa_source.jsonl` 之前。因此本次不修改 TTS、音频 QC、最终 Qwen3-Omni schema、stable split 等模块。

## 2. 新的最小 Domain Gate

生产 source 使用固定 Sujet revision：

```text
5e72431b6db6c339613ae809f4ae3c274ea1d0c7
```

对该固定快照执行已审计 lineage policy：

```text
KEEP:
- gbharti/finance-alpaca 且 source_row_id <= 62179
- adityamavle/FinRiskAnalysis 的 direct-QA

DROP / quarantine:
- gbharti/finance-alpaca 且 source_row_id >= 62180
- 未审计 upstream source
```

同时验证第 62180 行必须仍然是 canonical Stanford-Alpaca 的首条：

```text

```

完整 full scan 必须满足：

```text

KEEP    = 6,770
REJECT  = 32,031
```

任何变化都停止，不进入 TTS。

## 3. “保留所有金融数据”的严格含义

本版本保留的是当前 pinned Sujet 快照中**全部可审计、可证明为金融来源的 direct-QA**。它不使用关键词或 LLM 猜测把 Stanford-Alpaca 中偶然出现的金融主题样本重新纳入，因为那会降低数据来源可审计性。

被拒绝的 32,031 条会写入：

```text
failed/domain_rejections.jsonl
```

以后若需要做“最大召回”的第二阶段语义恢复，应对该 quarantine 单独审计，不应修改本版 finance-only release。
