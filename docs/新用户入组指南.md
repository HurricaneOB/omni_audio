## 一、服务器概况\(必读！\)

我们拥有一台 **8 GPU AI 计算服务器**，配备：

采用 **三大组三层架构**，`/mdr5` 和 `/ky200t` 镜像结构：

```Plaintext
/mdr5/                          /ky200t/
├── guest/                      ├── guest/
│   ├── users/用户名/           │   ├── users/用户名/checkpoints/
│   └── projects/项目名/        │   └── projects/项目名/
├── aifin/                      ├── aifin/
│   ├── users/用户名/           │   ├── users/用户名/checkpoints/
│   └── projects/项目名/        │   └── projects/项目名/
├── aifin_main/                 ├── aifin_main/
│   ├── users/用户名/           │   ├── users/用户名/checkpoints/
│   └── projects/项目名/        │   └── projects/项目名/
├── miniconda3/                 ├── models/          ← 777（所有组可读写）
                                ├── datasets/        ← 777（所有组可读写）
                                └── miniconda3/
```

**权限模型**：

- `models/`、`datasets/` → **2777 \+ SGID**（所有三大组用户可自由读写，新建文件继承 guest 组）

- `users/用户名/` → **700**（仅自己可读写）

- `users/用户名/checkpoints/` → **755**（他人只读）

- `projects/项目名/` → **770 \+ SGID**（仅项目组成员可读写）

**三级存储架构简介：**

1. **系统盘 ****`/`****（876G）**：仅存放 OS 和公共软件，**用户禁止写入**

2. **本地高速盘 ****`/mdr5`****（14T）**：你的家目录、虚拟环境、代码、临时 checkpoint（仅可进入自己的空间，无法进入他人的空间）

3. **NAS ****`/ky200t`****（200T）**：数据集（只读）、大模型权重、项目共享数据

4. **系统与环境层（系统盘 ****`/`****，876G）**

    - **用途**：仅存放操作系统、Root 用户的公共软件、Docker 镜像、全局 Conda 环境。

    - **规则**：**绝对禁止**普通用户在此目录下创建个人文件夹或存放数据。

5. **用户工作与高速缓存层（本地 14T 盘 ****`/mdr5`****）**\(仅可cd进入自己的空间，无法进入他人的空间\)

    - **用途**：读写速度要求高的场景。

    - **规划**：

        - `/mdr5/home/username/`：用户的个人工作区（代码、虚拟环境 `.venv`、小模型权重、日志）。

        - `/mdr5/scratch/username/`：临时计算区（训练产生的临时 checkpoint）。**Root 会设置定时任务（Cron），自动删除超过 7 天的文件**，防止本地盘被撑爆。

6. **大型数据与共享层（网络 200T NAS ****`/ky200t`****）**

    - **用途**：存放海量数据集、大型模型权重、跨用户共享数据。

    - **规划**：

        - `/ky200t/datasets/username/`：公共数据集（如 ImageNet, LAION）。**权限设为全局只读**，防止误删。

        - `/ky200t/projects/project_name/`：按课题组或项目划分。Root 创建 Linux 用户组（如 `group_projectA`），将该目录权限赋予该组，实现组内共享读写。

        - `/ky200t/checkpoints/username/`：专门存放几十上百 GB 的大模型权重。

        - `/ky200t/models/username/`：专门存放几十上百 GB 的大模型权重。

## 四、GPU 使用规范（必读！）

服务器共有 **8 张 GPU**，多人共享，请务必遵守：

### 4\.1 使用前：先查后占



nvidia\-smi          \# 查看所有 GPU 的占用情况和空闲显存

确认有空闲 GPU 后再启动你的任务。

### 4\.2 必须显式指定 GPU

**不要** 直接运行训练脚本占用全部 8 卡。必须通过环境变量声明你要用哪几张：

# ✅ 正确：只使用 GPU 0 和 1

CUDA\_VISIBLE\_DEVICES=0,1 python train\.py



# ✅ 正确：只使用 GPU 3

CUDA\_VISIBLE\_DEVICES=3 python train\.py



# ❌ 错误：可能抢占全部显卡

python train\.py

PyTorch 代码中也可设置：



import os

os\.environ\["CUDA\_VISIBLE\_DEVICES"\] = "0,1"

## \<a id="section\-8"\>\</a\>八、开发实用方法（推荐）

### 8\.1 SSH 免密登录

**第一步：在本地设备生成密钥**（如已有 `~/.ssh/id_ed25519.pub` 可跳过）



ssh\-keygen \-t ed25519 \-C "your\.email@example\.com"

# 一路回车即可，生成 \~/\.ssh/id\_ed25519（私钥）和 \~/\.ssh/id\_ed25519\.pub（公钥），windows路径在C:\\Users\\Windows\\\.ssh

**第二步：将公钥上传到服务器**

在 **本地设备** 执行：



# 方式 A：手动复制（推荐）

cat \~/\.ssh/id\_ed25519\.pub  \# 复制输出内容

然后将复制的公钥追加到 **服务器上** 你的 `mdr5/home/你的用户名/.ssh/authorized_keys`：



# 在服务器上执行

mkdir \-p \~/\.ssh

chmod 700 \~/\.ssh

echo "ssh\-ed25519 AAAA\.\.\.你复制的公钥内容\.\.\." \>\> \~/\.ssh/authorized\_keys

chmod 600 \~/\.ssh/authorized\_keys

或使用一行命令从本地上传（第一次需要输入密码）：



# 在本地设备执行

ssh\-copy\-id \-p 40022 你的用户名@服务器IP

**第三步（可选）：配置别名简化连接**

在 **本地设备** 创建 `~/.ssh/config`：



Host sufe\-server

HostName 服务器IP

User 你的用户名

Port 40022

IdentityFile \~/\.ssh/id\_rsa

之后直接 `ssh sufe-server` 即可，无需每次输 IP 和密码。

### 8\.2 文件传输

使用 `rsync` 替代 `scp`（增量同步，只传修改过的文件）：



# 本地 → 服务器

rsync \-avz \-\-progress \./本地目录/ user@server:/远程目录/



# 服务器 → 本地

rsync \-avz user@server:/远程目录/ \./本地目录/

### 8\.3 后台运行任务

**tmux（推荐）**—— 断网重连后会话不中断：



# 创建新会话

tmux new \-s myjob



# 运行训练

python train\.py



# 断连：Ctrl\+B 然后按 D（分离会话）

# 重连

tmux attach \-t myjob



# 杀掉指定名称的会话

tmux kill\-session \-t 会话名



# 建议任务完成及时清理tmux会话

**screen（备选）**：



screen \-S myjob

python train\.py

# 断连：Ctrl\+A 然后按 D

# 重连

screen \-r myjob

**nohup（简单后台）**：



nohup python train\.py \> train\.log 2\>\&1 \&



# 查看后台任务

jobs \-l

# 拉回前台

fg %1

### 8\.4 实用命令速查

**推荐工作流**：VSCode Remote SSH \+ tmux，远程开发永不掉线。

## \<a id="section\-11"\>\</a\>十一、常见问题（推荐）

**Q: 提示 CUDA Out of Memory？**A: 减小 batch\_size，或确认是否有人同时在用同一张卡（`nvidia-smi` 查看）。

**Q: ****`/mdr5/scratch`**** 下我的文件不见了？**A: 临时区超过 7 天的文件会自动清理。重要文件请存放于家目录或 NAS。

**Q: 我的家目录空间不足（超过 200GB 配额）？**A: 清理不需要的虚拟环境、checkpoint、日志。大模型权重转移到 `/ky200t/models/你的用户名/`。

**Q: 能否自己 ****`apt install`**** 装软件？**A: 不可以。普通用户没有 sudo 权限。需要的软件请用 `uv pip install` 在自己 `.venv` 中安装。
